## Specification
- Decisions: no-action vs fixed reserve vs integrated, obligations met, reserve kept, cost, each labelled with weight kind and cohort.
- Execution: bound terms shown before approval, keyboard-complete approval flow, provider state per leg, receipts, reconciliation result; unknown → incident view. Confirm approval and execute are separate explicit actions; no automatic POST retry on timeout. Resolve a timed-out execution by GET using its approval id; an approval timeout without an id requires operator resolution. PAID is reconciled as of a time, never irreversible finality. Token stays only in tab memory, never URL/storage/log/export; reads remain anonymous.
- Scenario-set cost is separate from current-plan fees. All-infeasible offers escalation, not approval. A branch result is not an executable approval; review a plan re-decided on the current observed snapshot.
- decide-execute.spec.js: approval disabled outside authority; unknown state renders the incident view; a fake-mode receipt is labelled 'simulated provider'.

## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.
