## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.
