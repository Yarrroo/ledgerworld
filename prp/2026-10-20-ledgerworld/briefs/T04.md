## Objective
Double-entry journals per entity and currency with a reservation lifecycle and the spendability answer S[a,c,t]: how much can reach this account in this currency by this time.

## Specification
- Model and rules exactly as system brief §5: accounts, buckets (settled, pending_in, pending_out, reserved, pledged, unknown), journals, postings, reservations (hold → commit | release | expire).
- Invariants (each a named test): every journal balances per currency; no posting without a journal; reserved ≤ settled per account; the same units are never pledged twice; unknown and stale balances are distinct from zero and lower authority.
- Two measures, never conflated (system brief §5): spendability S (free to commit; subtracts every committed pending_out) and projected cash P(t); the reserve floor is checked on P over the horizon, and an outflow clears only within S(now) and the floor headroom. Tables as in the design's `schema.sql`; settled is the sum of postings, never a stored column.
- Store: SQLAlchemy 2 Core over SQLite in tests and PostgreSQL in deploy (`LEDGER_DATABASE_URL`); one transaction per journal; `test_ledger_pg.py` is marked `pg` and runs in CI only.
- test_fixtures.py reproduces LF-1's expected block exactly (§6). Property tests (hypothesis) for balance and no-double-pledge.
- Register the test ids in checks/required.json under g1.

## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.
