# T09 · Branches with isolated memory and exact replay

Area: B · Simulation runtime · Phase P1 (Oct 28–30, Core journey) · Size L · Axis build · Goal g2 (The world is coupled) · Brief rank #4 · After: T08

## Objective
Checkpoint and fork a world; each branch has its own memory namespace; any branch can be replayed exactly from stored transcripts.

## Specification
- Checkpoint pins ledger and OASIS SQLite state, immutable actor memory records and namespace id, both clocks, RNG, scheduled-event cursor, pending C2 deliveries, an empty committed-boundary intent queue and transcript cursor. Fork restores the capture and writes copy-on-write; later parent memory writes cannot change the captured records.
- Memory is namespaced `world/<world_id>/branch/<branch_id>`; a sibling branch can never read another's writes (FakeGraphMemory enforces it in tests; the live adapter prefixes ids).
- Replay re-runs a branch from its transcripts with the model disabled and must produce byte-identical ledger journals.
- test_branches.py: sibling isolation, replay identity, a fork after a checkpoint does not change the parent.
- Register the test ids in checks/required.json under g2.

## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.
