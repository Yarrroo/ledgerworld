## Specification
- Operations and paths exactly as system brief §10; auth by `POST /api/v1/authentication/login` with `x-client-id` and `x-api-key` headers, bearer token cached until expiry minus 60 s.
- Mode switch `AIRWALLEX_MODE` = fake | sandbox; default fake, also when a key is set; `sandbox` with no key fails at start, never falls back silently. Production hosts are refused by code (allowlist: the sandbox base URL only).
- The fake keeps state (balances, transfers, conversions, payouts) and reproduces status lifecycles, idempotency by `request_id` **as the provider does it** (§10: a duplicate id is rejected with `duplicate_request_id`, or `409` while the first is in flight; never the original object), list-by-`request_id` lookup, the deposit and transfer-transition simulations, and the error envelope; scenarios: happy, timeout_after_accept, timeout_before_send, insufficient_funds, rate_limited, auth_fail, server_error, malformed_body. The client never repeats a POST after a timeout or a 5xx (`OutcomeUnknown`); it retries a 429 (backoff with jitter, ≤ 3) and one 401 after re-login, with the same `request_id`. The mode flips only on `AIRWALLEX_MODE=sandbox`, never because a key appeared.
- Every request body is built from integer minor units via one converter (decimal string on create calls; the deposit simulation's numeric `amount` derives from that same string); the API version header is pinned from `AIRWALLEX_API_VERSION`; the key never appears in an exception, log or trace.
- test_airwallex_fake.py: lifecycles, a replayed `request_id` is rejected and the original is found by list-by-`request_id`, timeout_after_accept leaves state unknown, the production host is refused.

## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.
