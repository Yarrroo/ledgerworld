One image for API, workers and the built frontend; PostgreSQL and Redis beside it; a host config the deploy task can apply.

## Specification
- Python 3.12 slim + built frontend; roles api | worker | sim chosen by `LEDGERWORLD_ROLE`; the sim role starts with AIRWALLEX_* scrubbed (T14).
- compose.yml for local runs (app, postgres:16, redis:7); deploy/host.toml for the host P4 names (default: Fly.io app + Fly Postgres + Upstash Redis, or one small VM running compose).
- Secrets by name only (§14). Health: `GET /api/v1/health` → {ok, mode, airwallex: fake|sandbox, model: scripted|live, version}.
- test_deploy_config.py (no docker on the build box): the Dockerfile and compose parse, every env name used exists in .env.example, the sim role's env list has no AIRWALLEX_*.

## Steps
1. Read the system brief and this brief in full
2. Write the Dockerfile and entrypoint
3. Write compose and host config
4. Write the tests
5. Run the accept and the merge gate; commit

## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.

## Done when
- `uv run pytest -q deploy/tests/test_deploy_config.py` exits 0
- `bash checks/merge.sh` exits 0
- Shipped result: The app can be stood up anywhere with names, not values.

## If it goes wrong
- If a task this one depends on has not produced what you need, stop and park this task naming that task id; never build another area's part yourself.
- If the accept cannot pass for a reason outside this task (a tool missing on the box, a contract gap, no key yet), park it with the measured reason instead of weakening the accept.
