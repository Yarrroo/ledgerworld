## Specification
- The round order of system brief §7.2, transactional: a round commits whole or not at all.
- Deterministic clearing: intents sorted by (priority class, simulated time, actor id); ties never depend on dict order.
- Every cleared action stores the observation hash and evidence ids that led to it, so a response traces back to the post that caused it.
- A `pending_in` expected at t that is not delivered in step 2 of that round is marked `overdue` before step 4. A request against an `offered` facility clears at step 7 through `lending.disburse` and arrives at the next round boundary; a lender `release` withdraws an offer.
- The coupled test uses an uncommitted advance (a draw on a committed line leaves K_p unchanged, so it cannot show the lender constraint).
- test_coupled.py::test_public_shock_traceable_response: a confidence post in round r is read by a borrower, whose draw plan changes in round r+1, and the lender's capacity changes; the trace links all three. Plus: a round that fails mid-way leaves the ledger untouched.
- Fault injection before round completion must restore ledger, OASIS SQLite, actor memory, both clocks, RNG, scheduled-event cursor, pending C2, intent queue and transcript cursor. Retry the same round with ScriptedModel and compare to a clean control from the same capture; no duplicate events, settlements, posts, memory entries or C2. These tests do not claim process-crash recovery.
- Capture before step 1; unhandled event/observation/actor failures and coordinator cancellation also abort the round. Close admission, cancel/join round-owned tasks and their children, then restore. If quiescence is unproved, refuse retry on that world. Use barriers to inject a sibling cleanup write before it terminates; restoration must remove it, and no writer may survive restoration. Preserve repaired malformed-output/no_action and rejected-intent semantics.
- Register the test ids in checks/required.json under g2.

## Don't
- Never put a secret in the repo, a log, a fixture, a trace or a test; `.env.example` names variables only.
- Never call the real Airwallex API, a real model or the hosted graph memory from a test the merge gate runs; tests use the fake transport, `ScriptedModel` and `FakeGraphMemory`.
- Money is integer minor units with an ISO currency everywhere; a float from a model never reaches a ledger posting or a provider request.
- A simulation process never holds an Airwallex credential and never imports `app.connectors.airwallex.live`.
- Edit only the files listed under Files you own, plus the one-line wiring your steps name; a wrong contract is fixed in `contracts/` with its example, and the commit says so.
- Upstream files are changed only where the system brief §3 allows it, and every changed upstream file is listed in `ATTRIBUTION.md` in the same commit.
- Never name a person, a team or the system that builds this repo in any repo file; it is a normal open-source project.
- Never push, merge or deploy; the engine publishes your branch.
