# Execution and approval UX verification

## Verdict

Mockups 06 and 07 are implemented on the existing `/execution` route. The dedicated acceptance command is green. Both themes were rendered and screenshots inspected at phone and desktop widths; the browser assertions exercise every supplied width.

## Reproduction

Before changing the view, `bash scripts/ux-check.sh e2e/ux/match-execution.spec.ts` failed at all widths: expected “Execution legs”, received “Money moved, with receipts”. The original page had no aggregate execution tracker and the approval dialog was one column. The regression test now passes on the rebuilt view.

## Evidence

- `npm --prefix frontend run test:unit -- tests/unit/decide-execute.spec.js`: 177 passed, including the fails-before/passes-after guards from both independent review rounds.
- `bash scripts/ux-check.sh e2e/ux/execution.spec.ts`: 33 passed, followed by all 12 judge-path/accessibility tests.
- `bash scripts/ux-check.sh e2e/ux/match-execution.spec.ts`: 9 passed, including a 4000-character label that previously overflowed at every width, followed by all 12 judge-path/accessibility tests. The desktop case explicitly resizes to 1487 px; tablet is 834 px and phone 390 px.

- `uv run python checks/no_secrets.py`: passed.
- `uv run python checks/attribution.py`: passed.
- `git diff --check`: passed.

All heavy checks were run through the shared heavy-command queue. The full `checks/merge.sh` was not run locally: the work order reserves it to the landing train. Its combined result is not claimed here.

## Defects found during the sweep

- A phone tap on a status tooltip also opened the enclosing receipt. Tooltip clicks now cancel the summary's default toggle; the test proves opening the tooltip leaves the receipt folded.
- The old judge-path selector treated a new `leg-pill` hook as a leg. The new hook uses the receipt namespace. Existing receipt mouse and keyboard selectors were aligned with the row chevron and its outer summary; the timed four-click path remains intact.
- Nested tooltips consumed Escape before modal dismissal. The modal listener now captures the key while the dialog is open; a unit regression and the existing browser focus test prove dismissal and focus return.
- The stricter aggregate status requires a settled leg, reconciliation flag, journal and no open incident. The banner, per-leg steps, hero counts and dialog terminal state now agree.

## Stability follow-up

The initial auxiliary repeat run failed because its undrained stdout pipe blocked the offline server's HTTP logger. Its first failure, video, partial original stdout and provenance are preserved in `stability-red/`; the RED result has not been replaced by a rerun. A pipe/drain/file-sink probe reproduced and isolated the launcher defect. With output redirected to a file, all 60 repeated Execution cases passed unchanged; see `stability-green.txt` and `stability-app.txt`. The regular acceptance command already uses a file sink and passed again after the review fixes.

## Deliberate omissions and boundaries

C6 does not supply journal amounts, so there is no provider/journal/difference comparison. A previously executed approval read supplies ids, snapshot and provider, but not the original entity, hash, expiry or complete terms: those fields are not reconstructed. A newly created C3 approval shows all bound terms before execution. Scenario-set fees are labelled as context, not a current-plan quote or an extra payment leg.

No dependency, provider call, API change, persistent data migration, backfill, deployment or publication. Simulation and Decisions implementation remain unchanged. Final combined-head acceptance belongs to the owning verification lane.
